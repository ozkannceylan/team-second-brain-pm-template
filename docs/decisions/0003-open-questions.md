# ADR 0003: Open Questions and Chosen Defaults

Where the specification left implementation choices open or offered trade-offs, we chose the lowest-friction generic default and made the alternative a 1-line configuration change.

| ID | Question / Ambiguity | Chosen Default | Rationale | How to Switch to the Alternative |
|---|---|---|---|---|
| **Q1** | **How should `board-keeper.yml` respond when a non-human actor moves a card to `Done` or assigns a user?** | **Visible audit (`auto_revert: false`)**: posts an issue comment naming the actor, adds the `policy-violation` label, and records the event in the Friday digest issue. | Avoids jarring state flips or revert loops if a human and bot touch a card within the same polling interval, while making violations impossible to miss. | Set `governance.auto_revert: true` in [`project/fields.yml`](../../project/fields.yml) (or pass `AUTO_REVERT=true`) to make `scripts/project_query.sh` automatically revert `Status` to `Doing` and unassign bot-added assignees. |
| **Q2** | **Where should poll state be stored to compare `Status` transitions without committing noise to `main`?** | **Inside the active `Week YYYY-WW` digest issue body** as a compact hidden HTML comment (`<!-- board-keeper:snapshot:{...} -->`), paired with GraphQL `fieldValueByName(name: "Status").creator.login`. | Committing a `.github/state/board-snapshot.json` file to `main` on scheduled runs pollutes `git log` and fails when branch protection requires PR reviews on `main`. Storing the snapshot in the digest issue body uses the Issues API (zero git commits). | No action needed. Cron activity on public repos is kept alive via `bot/inbox-capture` PR merges, human knowledge commits, `on: issues` events, and `workflow_dispatch`. |
| **Q3** | **What polling frequency balances responsiveness against GitHub Free's 2,000 Actions minutes/month on private repos?** | **Hourly during weekday business hours (`0 8-18 * * 1-5`)** = 11 runs/day × 22 weekdays = 242 cron runs/month (~332 total billed min/mo including issue events and PR checks, or **16.6% of Free cap**). | Leaves >80% of a private Free org's monthly Actions minutes available for code CI/CD while reacting immediately (`0s` latency) to issue assignments, closes, and `status:blocked` labels via `on: issues`. | Change `cron: '0 8-18 * * 1-5'` in [`.github/workflows/board-keeper.yml`](../../.github/workflows/board-keeper.yml) to `'*/30 8-18 * * 1-5'` (~574 min/mo) or `'*/15 * * * *'` on public repos (0 billed minutes). |
| **Q4** | **How do non-git users capture learnings for Definition of Done (DoD) without touching git?** | **Comment `Learned: <takeaway>` (or `Decision:` / `Knowledge:`) on the issue card** before or when moving it to `Done`. | Works identically in the GitHub mobile app and desktop browser in <30 seconds. `scripts/project_query.sh` extracts the comment into `inbox/issue-<N>.md` on a single consolidated branch/PR (`bot/inbox-capture`) and populates the card's `Knowledge link` field automatically. | Users who prefer the browser file editor can click `_templates/inbox-note.md` and create a file in `inbox/` directly, or paste an existing `knowledge/area-a/...` path into `Knowledge link`. |
| **Q5** | **What aging thresholds and anti-spam cooldowns apply to `Blocked` and `Doing` cards?** | **`Blocked` ≥ 3 days = warning comment; `Blocked` ≥ 5 days = `escalated` label + mention `@ORG/maintainers`; `Doing` with no update ≥ 5 days = gentle check-in; cooldown = max 1 bot comment per card per 3 days.** | Matches the 2-week pilot cadence (a 3-day blocker is 30% of the sprint/pilot) while the embedded `<!-- board-keeper:alert:YYYY-MM-DD -->` marker prevents daily notification fatigue. | Edit `blocked_warn_days`, `blocked_escalate_days`, `doing_stale_days`, `alert_cooldown_days`, and `escalation_mention` in [`project/fields.yml`](../../project/fields.yml). |
| **Q6** | **Should blank issues be allowed in `.github/ISSUE_TEMPLATE/config.yml`, and how should form files be named?** | **`blank_issues_enabled: true`** with exact form filenames `task.yml`, `bug.yml`, `blocker.yml`, `decision.yml`. | Keeps the 4 structured forms front-and-center while allowing a 15-second title-only issue capture on a phone during a live incident or meeting. | Set `blank_issues_enabled: false` in [`.github/ISSUE_TEMPLATE/config.yml`](../../.github/ISSUE_TEMPLATE/config.yml) if strict form selection is desired; prefix filenames with `01-`..`04-` to override alphabetical ordering (F8). |
| **Q7** | **How many saved Project views should be created by default?** | **3 views:** `1. Board` (Kanban by `Status`), `2. Stand-up Dashboard` (Table grouped by `Status`: Blockers, Doing, Done last 7d), and `3. Needs Attention` (Table of governance/hygiene exceptions). | Gives one primary daily view (`2. Stand-up Dashboard`), one drag-and-drop kanban (`1. Board`), and one zero-inbox hygiene view (`3. Needs Attention`) within the ≤3 view budget. | Edit [`project/views.yml`](../../project/views.yml) before running `./scripts/setup-project.sh`, or delete/customize views in the Project UI. |
| **Q8** | **Where does the Second Brain folder skeleton live in the repository?** | **Directly at the repository root** (`inbox/`, `knowledge/area-a/`, `decisions/`, `standards/`, `_meta/`, `_templates/`), while template design ADRs live in `docs/decisions/`. | Because `ORG/REPO` *is* the unified Second Brain + Project Management repository, placing `inbox/`, `knowledge/area-a/`, `decisions/`, `standards/`, `_meta/`, and `_templates/` at root avoids awkward `knowledge/knowledge/area-a/` double nesting. | If embedding inside an existing application monorepo, move those folders under a `docs/second-brain/` prefix and update the path list in `.github/workflows/validate-knowledge.yml`. |
| **Q9** | **Which YAML parser do the shell scripts depend on?** | **`yq` (mikefarah `yq` v4, pre-installed on GitHub Actions `ubuntu-latest`)** plus `jq` and `gh`, with a `python3` fallback in `validate_knowledge.sh`. | Avoids fragile `grep`/`sed` regexes on YAML files while requiring zero `pip install` steps on GitHub-hosted runners. | Install locally via `brew install yq jq gh` (macOS) or `snap install yq` / GitHub release binary (Linux). |
