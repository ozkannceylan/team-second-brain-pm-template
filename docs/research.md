## 2. Known Limitations of GitHub Projects v2 and Our Workarounds

| Limitation | Platform Reality | Our Workaround in This Template |
|---|---|---|
| **1. No `projects_v2_item` trigger in GitHub Actions (F1)** | Dragging a card between columns on the Project board does not fire a repository Actions workflow. | Combine instant `on: issues: [assigned, unassigned, closed, reopened, labeled]` triggers with a consolidated weekday hourly GraphQL poll (`board-keeper.yml` + `scripts/project_query.sh`). Mobile users can also apply label `status:blocked` for instant 0-latency `Blocked` stamping. |
| **2. `GITHUB_TOKEN` cannot access Projects v2 (F2)** | Default workflow token returns `403` on `projectV2` GraphQL queries/mutations. | Use `actions/create-github-app-token@v1` (short-lived 1h org App token) or `PROJECT_PAT` fallback. If the token expires, an `if: failure()` step uses the never-expiring `GITHUB_TOKEN` to open a visible alert issue. |
| **3. GraphQL returns current field state, not full transition history** | Polling sees current `Status` and `fieldValueByName(name: "Status").creator.login`, not intermediate flips between polls. | Turn **OFF** built-in *Item closed → Done* and *PR merged → Done*, check `Status.creator.login` on every poll, and persist poll state inside the weekly digest issue body (`<!-- board-keeper:snapshot:{...} -->`) without committing noise to `main`. |
| **4. Soft WIP limits only (F6)** | Exceeding a column limit turns the count red but does not block dragging. | Set `Doing` limit to `2 × team_size` for visual red feedback and review `Doing` grouped by `Assignees` at minute 3 of daily stand-up. |
| **5. No native column dwell-time chart & Insights ignores archived items (F7)** | Insights cannot chart "days spent in `Blocked`", and archiving items immediately erases chart history. | Auto-stamp `Blocked since` (Date field) to track exact blocker age (`3d` warn, `5d` escalate), and keep `Done` cards for **30 days** before auto-archiving (`status:Done updated:<@today-30d`). |
| **6. Auto-add cap (1 on Free) & no backfill (F4)** | GitHub Free allows 1 auto-add rule per project and does not import pre-existing issues. | `scripts/setup-project.sh` links the repo; existing issues can be bulk-added once via `gh issue list`, and a multi-repo Actions auto-add snippet is provided in [`docs/optional/experimental.md`](optional/experimental.md). |
| **7. Scheduled workflows disable after 60 days of repo inactivity** | Public repos pause `schedule:` crons if no commits occur for 60 days. | Co-locating the Second Brain (`inbox/`, `knowledge/`, `decisions/`) in the same repo plus `bot/inbox-capture` PR merges keeps activity fresh; `on: issues` and `workflow_dispatch` remain active. |

## 3. Alternatives Considered (≤ 6 Lines)

1. **GitHub Projects v2 + Repo Markdown (Chosen):** Zero extra SaaS logins or servers; native `#issue` links to PRs and `knowledge/`; mobile app included; official MCP server with `projects` toolset (F14).
2. **Linear / Jira / Shortcut:** Richer native workflow rules and cycle-time charts, but splits tasks from the Markdown Second Brain, adds per-seat SaaS cost, and requires syncing two permission models.
3. **GitLab Issues & Boards / Plane:** Strong self-hosted or all-in-one alternatives, but require migrating code/org hosting away from GitHub or maintaining separate infrastructure.
4. **Kanzo (`emanuele-em/kanzo`, F18):** Lightweight local Go + SQLite kanban with MCP server (AGPL-3.0), but single-user with no authentication, RBAC, or mobile web UI—unusable as a shared 5–15 person team board.
5. **Obsidian Kanban (`mgmeyers/obsidian-kanban`):** Stores boards as a single Markdown file in git, which causes constant merge conflicts when 5–15 people or bots move cards concurrently and fails the "no git for non-writers" requirement.
